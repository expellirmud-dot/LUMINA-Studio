# Impeccable-Inspired Level 3 Reference

Use these topics when the dashboard needs stronger design judgment than the base visual rules provide.

## 1. Design Vocabulary

- Teach the model a small, shared vocabulary for layout, tone, motion, and hierarchy.
- Ask for specific actions instead of vague "make it nicer" prompts.
- Keep product dashboards in a product mode, not a brand-experiment mode.

## 2. Slop Detection

- Reject generic gradients, shiny blobs, and decoration that hides information.
- Flag designs where the background tries to become the main event.
- Prefer clear surfaces, stable spacing, and readable text over novelty.

## 3. Live Iteration

- Review a real screen, then refine the exact panel or component that needs attention.
- Keep changes small enough to inspect in diff form.
- Favor iterative improvements over full visual rewrites.

## 4. Source-Writable Design

- Design changes should be traceable in source, not trapped in screenshots.
- Keep generated output reviewable and reversible.
- Treat visual edits as code changes that can be diffed, accepted, or rejected.

## 5. Product Mode vs Brand Mode

- Use product mode for dashboards, tools, and operational consoles.
- Use brand mode only when the task is explicitly about identity or marketing.
- Do not let branding override the user's ability to act quickly.

## 6. Production Review

- Verify contrast, hierarchy, and readability in the actual app.
- Make blockers and status states visually unambiguous.
- Ensure the final result still feels calm and operational after multiple edits.

## 7. Plugin Boundary

- Only suggest plugins when they could help.
- Never invoke a plugin automatically unless the task card explicitly allows it.
- Keep plugin choice as an explicit decision, not a hidden skill side effect.
