# Dashboard Shell and Panel Hierarchy

Use these topics when designing a dense operational dashboard.

## 1. App Shell

- Keep the shell simple and stable.
- Separate top-level navigation, main content, and utility rail.
- Avoid competing hero treatment inside command surfaces.

## 2. Panel Hierarchy

- Make the primary action area visually dominant.
- Keep secondary evidence and logs quieter.
- Use clear surface contrast instead of decorative effects.

## 3. Command Center Layout

- Place task state, command builder, and evidence summary in predictable zones.
- Keep the current task visible without requiring page search.
- Prefer stacked sections over floating widgets when the dashboard is dense.

## 4. Task Detail Sections

- Show status, scope, allowed files, and blockers near the top.
- Group commands separately from reports and timeline evidence.
- Make it obvious what is read-only and what is actionable.

## 5. Empty, Loading, and Error States

- Show what is missing, not just that data is missing.
- Keep empty states short and actionable.
- Treat errors as operational states, not decorative alerts.

## 6. Motion Safety

- Use motion only to clarify state change.
- Keep transitions short and subtle.
- Respect reduced motion preferences.

## 7. Do Not Over-Design

- Avoid excessive glow, glass, or animated noise.
- Avoid splitting the same information across too many surfaces.
- Optimize for clarity under repeated daily use.
